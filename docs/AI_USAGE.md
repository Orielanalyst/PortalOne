## How output is controlled

25 October mission-update increment: Codex integrated the already retained
Meterless World Model into browser plan dependencies, source drift and replacement
lineage; reused the acquired p-retry package for bounded source-read recovery;
and implemented streamed citation-handle resolution, historical download guards,
publication checks, coordinate inventories and live/UI/native GIS verification.
Lightning and Ultra generated the actual findings/plans/critiques/report in the
recorded runs. Code maps supplied source handles and builds inventories/diffs;
it does not invent evidence. Failed citation, output-limit, ISO-date/control
validation and final-source-read rehearsals are preserved and fixed forward.
The final live proof has an exact commit and hashes. Field truth and operational
approval are not established by that proof.

25 October committee increment: Codex acquired Streamdown, SSE/partial-JSON/diff
components and the PDF runtime, implemented native streaming, document/source
storage, the bounded committee graph, GIS/PDF export and browser checks. Nemotron
Lightning wrote investigation/dialogue output; Ultra wrote plans, independent
critiques and the final narrative. Roles use separate model calls and fresh
evaluator source queries; source validation, geometry, diffs, hashes and export
are code. The accepted run needed one visible source-check correction, followed
by plan v1, critique, v2, acceptance with gaps and export. Formatting editions
changed presentation and generated appendices without changing that narrative
or geodata. Named proposed counterparties remain unverified suggestions.

Failed rehearsals exposed citation omissions, incorrect uncertainty wording,
model output limits and Nightshift's generic quality/scaffold behavior. These
failures are preserved locally and fixed forward; only the later native run is
claimed as the streaming proof. Codex inspected installed runtime source to
identify that behavior; no proprietary source was copied into the repository.
Full native-model receipts distinguish generation from cache replay. Source
documents, identities and provider credentials stay in their existing boundaries.

25 October implementation: Codex acquired/pinned Leaflet and map parsers, prepared
the attributed OSM extract, created the private Kobo form after the human saved
their token, and implemented intake, SQLite persistence, the supervisor/tool-worker
graphs, tests, monitoring, explicit replay and the connected interface. Live
Nightshift responses reported Nemotron 3.5 Lightning and Nemotron 3 Ultra; the
model selected bounded delegations and public reasons. Geometry, reconciliation
and readiness checks are code. Transport tests are explicit demonstrations, not
claimed field incidents. No reporter messages, provider terms, account billing,
public sharing or dispatch approval were automated.

- The human sets scope, architecture and acceptance criteria.
- AI-written work receives typechecks, tests, inspection and the mandatory
  pre-push gates. Intermediate failures and forward fixes remain in history.
- The safety evaluator is deterministic and unit-tested. The model cannot approve
  a plan; it can only propose one.
- Secrets are never pasted into prompts or committed. API keys live in `.env`
  (ignored) or, for NVIDIA, in Nightshift's Providers tab.

## Responsibility and attribution

26 October continuation: Codex implemented the public-source, road relationship,
mission-input/feasibility and exact-version operator-review extensions. Native
Nightshift/Nemotron runs exercised conversation, investigation, planning,
evaluation and report generation; deterministic code performs source checks,
calculations, version binding and GIS validation. Rejected drafts and model
receipts remain local. A real UI rejection records a source-label error found
during visual review. The combined approval/revision/invalidation acceptance gate
remains open; implementation and component passes are not represented as final
acceptance or operational authority.

The human owns project direction and final acceptance. AI has contributed
architecture, scope and demo suggestions as well as code and documents; those
contributions are not represented as exclusively human-authored. A commit made
with the user's configured Git identity does not by itself establish authorship
of every line. Planned model integrations in the table remain unimplemented
until their verification evidence exists.
